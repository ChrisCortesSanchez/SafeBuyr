# Architecture (Baseline)

The single-page view of SafeBuyr as it exists today — the Phase 0 baseline every
later tool and scan result is judged against. Two functionally identical
e-commerce apps run side by side: one planted with flaws, one hardened. The gap
between scanning them is the project's evidence.

## Where secrets live today

- **Vulnerable app:** `SECRET_KEY = 'vulnerable-secret-key-change-this'` —
  hardcoded on purpose (VULN-007, the planted weak-secret flaw).
- **Hardened app:** `SECRET_KEY = os.urandom(32)` — random per process, never
  persisted.
- **No external credentials.** No `.env`, API keys, or cloud secrets are tracked
  (`git ls-files` confirms none). Seed users use fake `@safebuyr.*` emails and
  throwaway passwords. This is why active scanning is safe to run locally.
- Later phases (cosign keyless signing, Kubernetes Secrets) will introduce real
  secret handling; this baseline deliberately has none.

## Persistence

SQLite files (`app/data/ecommerce.db`, `app/secured/data/ecommerce_secure.db`)
are generated by the seed scripts and are **not** tracked in git. A clean clone
has no database until `make init-db` (or `make setup`) runs.

## CI pipeline (`.github/workflows/ci.yml`)

Runs on every push and PR to `main`/`develop`, two sequential jobs:

```
push / PR
   │
   ▼
┌─ code-quality ──────────────────────────────┐
│  black --check · flake8 · bandit -r app/     │  (advisory: `|| true`)
└──────────────────┬───────────────────────────┘
                   ▼
┌─ regression-tests ──────────────────────────┐
│  seed both DBs                               │
│  start vulnerable (5001) → test_vulnerable   │
│  start hardened  (5002) → test_secure        │
│                         → test_scanner       │
└──────────────────────────────────────────────┘
```

The quality job is currently advisory (failures don't block); the regression
job is the real gate. Hardening these into enforced gates — and adding Semgrep,
Trivy, Gitleaks, ZAP, SBOM/signing, and admission control — is the DevSecOps
build plan that follows this baseline.

## Current state vs. the build plan

| Layer | Today (baseline) | Build-plan target |
|-------|------------------|-------------------|
| SAST | `bandit` (advisory) | Semgrep w/ custom taint rule, SARIF to code scanning (Phase 1) |
| Secrets / deps | none | Gitleaks history scan + Trivy/pip-audit gate (Phase 2) |
| Container | `docker/Dockerfile.*` | multi-stage, non-root, distroless, pinned digest, Trivy gate (Phase 3) |
| DAST | own 8-phase scanner | + OWASP ZAP baseline + authenticated active scan (Phase 4) |
| Supply chain | none | Syft SBOM + cosign keyless signing + attestation (Phase 5) |
| Runtime | local processes | kind cluster, security context, NetworkPolicy (Phase 6) |
| Admission | none | Kyverno: reject unsigned / non-compliant images (Phase 7) |
